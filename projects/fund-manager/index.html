使用说明

本工具包含相互独立的“活动经费”和“实习生工资”两个本地记录模块，不是正式财务系统。

重要：业务数据只保存在当前浏览器本地。更换电脑、清理网站数据或重置浏览器都可能导致数据不可访问，请优先阅读下方“本地数据与备份”并定期执行完整备份。
本地数据与备份（必读）快速开始预算导入活动管理报销与无法报销资金平账催办隐私模式备份恢复统计导出实习生工资
请先确认你理解本地数据的风险本工具没有网络数据库。浏览器里的数据一旦被清理，网页本身无法从服务器替你恢复。

一、本地数据与备份（必读）

  • 业务数据只保存在当前浏览器本地，不会上传到网络数据库。
  • 更换电脑、清理浏览器网站数据、重置浏览器配置或浏览器故障，都可能使本地数据无法继续访问。
  • 活动经费应定期点击“完整备份”保存工作簿；实习生工资模块当前独立保存在另一套本地数据库中。
  • 执行完整恢复前，系统会先要求保存一份“恢复前自动备份”，用于误恢复后的回退。
  • 本工具不保存完整修改历史，只保存当前值和各可编辑字段的最后编辑日期。
  • 金额以人民币元显示，最多两位小数；内部按“分”的整数计算。预算、首次预支、无法报销、单价和总价不接受负数；“后续补款”允许正负数，正数表示后续补款，负数表示实际退回。

二、快速开始

  1. 在首页点击“新建活动”，填写活动名称，并可添加任意数量“活动标签”；可以一键选择已经使用过的标签，也可以现场输入并创建新标签。也可以从预算电子表格直接创建活动。
  2. 活动编号自动取现有最大编号加 1；创建日期自动取电脑当天日期。
  3. “初步预算”用于保留计划值；“实际支出”由支出清单中的总价自动汇总，两者互不覆盖。
  4. 资金记录分为“首次预支”和“后续补款”；系统自动计算“已拨付金额 = 首次预支 + 后续补款”。后续补款允许为负数，用于记录实际退回的资金。
  5. 学生报销时，在支出清单中核对实际金额并勾选“已报销”。系统自动累计已报销金额。
  6. 如果某部分实际支出已经确定无法报销，可在活动详情填写“无法报销”。系统自动计算剩余“待报销”。
  7. 如果全部未报销余额都确定无法报销，可勾选“自动将未报销余额计入无法报销”。开启瞬间系统立即计算“无法报销 = 实际支出 − 已报销”。界面上的“无法报销”直接显示这个公式结果，不再读取原来的手工金额；待报销立即归零。
  8. 系统始终实时显示资金差额：“已拨付金额 − 已报销 − 无法报销”。因此待报销尚未处理时，该部分仍包含在待退 / 待补差额中；当剩余待报销转为“已报销”或“无法报销”后，资金差额会同步变化。实际退款以负数记入“后续补款”，补款记正数；差额为 0 时自动平账。
新版核心关系：实际支出 = 已报销 + 无法报销 + 待报销；已拨付金额 = 首次预支 + 后续补款。预支不再用来统计实际支出。

四、活动查看与批量管理

主页查看与筛选

主页每个活动对应一张活动卡片。卡片四项核心金额为“实际支出、已拨付、已报销、待报销”。普通模式下金额统一打码。

可以按活动名称或编号搜索，也可以按一个或多个“活动标签”、活动状态和创建日期筛选。多标签采用“同时满足（AND）”逻辑，例如同时选择“心理协会”和“2026秋季”时，只显示同时拥有这两个标签的活动；也可筛选“未设置标签”的活动。标签、状态、时间和搜索条件可以组合使用。主页筛选的本质是生成“当前结果集”：活动卡片、顶部四项统计、按标签分组和按标签统计都以这同一批活动为输入。

主页统计统一为“实际支出合计、已拨付合计、已报销合计、待报销合计”。未设置筛选条件时，当前结果集自然就是全部活动；存在筛选条件时，统计立即跟随当前结果变化。活动管理中的手动勾选只用于批量导出和删除，不改变统计范围。

按标签分组

“按标签分组”是独立的主页展示开关，只改变当前结果集的呈现方式，不改变筛选条件和统计口径。开启后，每个标签成为一个动态分组并显示本组的四项金额汇总；一个活动如果拥有多个标签，会同时出现在多个标签分组中。没有标签的活动进入“未设置标签”分组。

按标签统计

点击“按标签统计”会直接统计当前结果集中的全部标签，不再另外选择统计范围。弹窗先显示当前结果整体汇总及各标签的汇总对比；可直接导出为 XLSX。标签统计允许同一个活动计入多个标签，因此各标签汇总之间可能重复包含同一活动，不能把所有标签行再次相加当作当前结果集总额。

“未结清”指仍有待报销，或资金差额仍不为 0（待退 / 待补）的活动。资金差额会在待报销尚未归零时照常显示。空白的新活动不自动算作待处理。

活动管理已经集中到主页

  1. 点击主页工具栏中的“活动管理”。普通模式下需要先输入密码；秘密模式下可直接进入。
  2. 进入活动管理后，每张活动卡片会出现选择框，可逐个勾选或“全选当前结果”。
  3. “导出选中”生成“总览 + 每活动一张工作表”的统计工作簿。
  4. “删除选中”会二次确认后永久删除活动及其全部支出数据。

单个活动详情

  • 活动标签：每个活动可以拥有任意数量标签。新增或编辑活动时，可快速选择已有标签，也可现场创建新标签；主页可多标签 AND 筛选、按标签动态分组，并可对当前结果集一键执行按标签统计。标签只用于组织、筛选和统计，不参与任何财务公式。
  • 初步预算：计划参考值，可编辑；不随支出变化自动修改。
  • 实际支出：所有支出明细“总价”的合计，自动计算。
  • 首次预支 / 后续补款：记录资金流。首次预支不接受负数；后续补款可正可负，正数表示追加拨款，负数表示实际退回。系统自动得到已拨付金额。
  • 已报销：所有已勾选支出“总价”的合计，自动计算。
  • 无法报销：活动级金额字段，可手工填写，也可由“自动将未报销余额计入无法报销”自动计算。
  • 待报销：实际支出 − 已报销 − 无法报销，自动计算且不可直接编辑。

五、报销与无法报销

  1. 进入对应活动详情，找到实际已经报销的支出。
  2. 如实际金额与原记录不同，先修改该条支出的“总价”；实际支出会立即同步变化。
  3. 勾选“已报销”后，该条总价计入已报销金额，并自动记录当天为报销日期。
  4. 取消“已报销”时，原报销日期自动清空；以后再次勾选时，日期改为再次勾选的当天。
  5. 如果已经明确有一部分钱无法报销，在活动级“无法报销”字段填写金额。该值不得超过当前尚未报销的金额。
默认模式下“无法报销”是自由金额字段。系统始终保证：无法报销 ≤ 实际支出 − 已报销。

剩余全部无法报销

勾选“自动将未报销余额计入无法报销”后，“无法报销”变为只读，并实时保持：

无法报销 = 实际支出 − 已报销

因此“待报销”自动变为 0。以后即使支出总价或已报销金额变化，该字段也会跟随重新计算。取消勾选时保留当前金额，只重新开放手工编辑。

六、资金平账

资金差额始终实时显示，不需要等待“待报销”归零：

资金差额 = 已拨付金额 − 已报销 − 无法报销

  • 差额大于 0：显示“待退”，表示当前已拨付金额高于已经完成处理的支出。
  • 差额小于 0：显示“待补”，表示已经完成处理的支出高于当前已拨付金额。
  • 差额等于 0：显示“已平账”。

“待报销”属于已经发生但尚未完成处理的支出，因此在它被转为“已报销”或“无法报销”之前，不从资金差额中扣除。系统不提供“已退 / 已补”或人工结清按钮；实际退款或补款直接修改“后续补款”：补款填正数，退回填负数。

例如：预支 6000、已报销 5777、无法报销 0、待报销 111 时，资金差额 = 6000 − 5777 − 0 = 待退 223；开启自动无法报销规则后，“无法报销”立即变为 111，资金差额同步变为待退 112。

七、催办规则

网页每次首次打开或刷新时，都会读取电脑当天日期并重新判断全部活动。活动创建满一个自然月后：

  • 如果资金差额不为 0，按当前差额进入待退 / 待补催办；如果此时同时还有待报销金额，主状态仍显示待退 / 待补，并在下方辅助显示“其中仍有 X 待报销”；
  • 如果资金差额已经为 0，但仍有“待报销 > 0”，进入待报销催办；
  • 资金差额为 0 且待报销为 0 时，不再催办。

旧版“经费已手动处理”开关已取消。旧数据中曾经勾选该开关的活动，升级后会转换为“自动将未报销余额计入无法报销”。资金是否结清只看资金差额是否为 0。

八、普通模式、活动详情与秘密模式

  • 普通模式主页：金额统一打码，适合学生在旁边时查看活动列表和状态。
  • 普通模式进入活动：需要输入密码。验证成功后，仅本次活动详情显示真实金额；返回首页后，主页继续打码。
  • 秘密模式：输入密码进入后，主页显示真实金额，进入活动详情不再重复验证。
  • 刷新：刷新页面后恢复普通模式，避免下次打开页面时直接暴露金额。

密码校验用于日常屏幕隐私保护，不等同于专业的数据加密系统。

九、完整备份与恢复

完整备份

点击“完整备份”会生成一个电子表格工作簿，其中包含一个“总览”工作表，以及每个活动各自的“活动_编号”工作表。新版备份保存活动标签及其最后编辑日期，以及初步预算、首次预支、后续补款、无法报销、自动无法报销规则、支出、备注、报销日期及最后编辑日期；不再保存独立的退补完成状态。

完整恢复

通过“导入工作簿”选择本工具生成的完整备份文件。恢复采用整体覆盖方式，不与当前数据自动合并。

新版可以恢复当前新版备份，也兼容旧版完整备份。旧版“活动归属”会自动迁移为一个同名标签；旧“预支金额”迁移为“首次预支”，后续补款默认为 0；旧“经费已手动处理”会迁移为“自动将未报销余额计入无法报销”；旧备份中的“退补已完成”字段仅兼容读取并忽略。

真正覆盖当前数据以前，系统会先要求把当前状态另存为一份安全备份。如果用户取消安全备份保存，则恢复操作也会取消。

完整恢复会替换当前浏览器中的全部活动数据。请确认选择的是正确备份文件。

十、统计导出

“按时间导出”和“导出选中”会同时导出活动标签，以及新版财务字段：初步预算、实际支出、首次预支、后续补款、已拨付、已报销、无法报销、待报销、资金差额和处理状态。

“按标签统计”导出始终使用当前结果集。生成的 XLSX 第一张为“全部活动汇总”，其中当前结果的每个活动只出现一次，并在最下方给出去重后的整体汇总；随后每个标签各占一张工作表，表内只列活动级整体数据，不展开单品支出，最下方是该标签的汇总。多标签活动会分别出现在多个标签工作表中；无标签活动使用“未设置标签”工作表。

统计导出适合人工阅读和归档；完整备份用于无损恢复系统。两者用途不同。

十一、实习生工资管理

实习生工资模块与活动经费模块完全独立，使用单独的本地数据库，不共享活动、标签、财务公式或统计结果。模块仍以记录为中心；人员无需单独建库，任务则使用独立的“任务预设表”降低重复输入。

  • 收入记录：登记日期、收到金额和备注；每次到账单独保存一条记录。
  • 工资记录：登记日期、实习生、任务、数量、工资标准、支付状态和备注。选择任务预设后自动带入计量单位和“每单位折合工时”；标准工时 = 数量 × 每单位折合工时，不允许手工直接填写标准工时；工资金额再按“标准工时 × 工资标准”自动计算。
  • 快速复用：历史记录中出现过的实习生会自动成为快捷选项；任务通过“任务预设”快速选择。工资标准默认继承上一条工资记录的标准，但可以随时修改。
  • 任务预设：预设表保存工作类型、任务名称、计量单位、每单位折合工时和说明，支持手动新增、编辑、删除。内置初始规则包括推文排版 2 小时/篇、推文排版审核 1 小时/篇、推文文案 4 小时/篇、现场志愿者 1 小时/小时、前期策划 16 小时/月、统筹管理 16 小时/月、坐班 1 小时/小时。工资记录中第一次保存一个新的任务名称时，会自动把该任务当前规则增加到预设表。
  • 周工时提醒：学期中每人每周上限 8 小时，假期（含寒暑假）上限 40 小时。超过上限不阻止保存，只把首次导致该周累计越线的那一条记录标红提醒，其他记录不受影响。
  • 已支付仍可修改：“已支付”只是记录状态，目前不会锁定记录。
  • 三个独立子页面：“记录流水”负责新增、编辑、筛选具体记录；“任务预设”单独维护任务规则；“统计分析”拥有自己的统计筛选，不与流水筛选耦合。
  • 统计分析：支持两套独立的时间入口：年份/月份用于快速查看固定年月，也可以填写开始日期/结束日期分析任意时间段；只要起止日期有任一项填写，就优先按自定义日期范围统计，清空后恢复年月筛选。还可按实习生、任务和支付状态组合筛选；提供期间收入、应付/已支付/未支付、标准工时、人数、任务数和超限提醒等指标，并进一步提供时间趋势、按实习生分配、按任务分析、未支付明细和周工时超限明细。
  • 统计导出：“统计分析”页可将当前分析范围导出为 XLSX，包含分析汇总、时间趋势、按实习生、按任务、工资明细、收入明细、未支付明细和超限提醒等工作表。
工资数据是独立记录，不参与活动经费的任何筛选、标签、平账或统计。

财务模型

本页定义程序中各金额字段的业务含义和固定计算关系。它与“使用说明”并列，用于查账、验算和后续维护。

模型原则字段定义固定公式无法报销资金平账状态与催办完整示例旧数据迁移

一、模型原则

新版把“实际花了多少钱”“报销到了什么程度”“一共拨了多少钱”“最终应退还是应补”拆成互不混淆的四件事。

  • 初步预算只表示计划值。
  • 实际支出只由支出明细决定，不由预支或报销状态决定。
  • 已拨付金额表示当前净拨付资金：首次预支加上后续补款；后续退款以负数冲减。
  • 报销状态把实际支出分成已报销、无法报销和待报销。
  • 活动标签用于组织、组合筛选、动态分组和按标签统计；一个活动可以拥有任意数量标签，标签不参与任何财务计算。
  • 主页统计范围由当前搜索、多标签、状态和日期筛选共同决定；没有筛选时当前结果集自然等于全部活动。按标签分组只改变展示，按标签统计直接使用当前结果集，二者都不创建额外的统计范围。

二、字段定义

字段来源是否可编辑含义
初步预算用户 / 预算导入是活动最初计划支出
实际支出支出明细总价合计否实际已经发生的全部支出
首次预支用户是活动首次拨出的资金
后续补款用户是后续资金调整：正数表示补款，负数表示实际退回
已拨付金额自动否当前净拨付金额 = 首次预支 + 后续补款
已报销已勾选支出合计否已经完成报销的实际支出
无法报销用户 / 自动条件性确实发生但确认不能报销的金额
待报销自动否仍需继续处理的报销金额
资金差额自动否已拨付金额 − 已报销 − 无法报销；归零即平账

三、固定公式与不变量

公式 1：实际支出 = 所有支出明细总价之和
公式 2：实际支出 = 已报销 + 无法报销 + 待报销
公式 3：已拨付金额 = 首次预支 + 后续补款
公式 4：资金差额 = 已拨付金额 − 已报销 − 无法报销

程序必须始终维持这些等式成立。待报销和已拨付金额均不允许手工输入。

四、无法报销的活动级规则

本版本只实现活动级无法报销金额，不为每一条支出增加“无法报销”状态。

  • 默认状态下，“无法报销”可自由填写，但不能超过“实际支出 − 已报销”。
  • 勾选“自动将未报销余额计入无法报销”后，系统立即把“无法报销”改为“实际支出 − 已报销”。对外显示直接取公式值而不是旧字段值，待报销立即变为 0。
  • 自动模式下，支出金额或已报销金额变化时，“无法报销”实时重新计算，使待报销始终为 0。
  • 取消自动模式后保留当前无法报销金额，只恢复手工编辑。

五、资金平账

资金差额以已经完成处理的支出为基准实时计算。待报销虽然属于实际支出，但尚未进入已报销或无法报销，因此暂不从资金差额中扣除。

资金差额 = 已拨付金额 − 已报销 − 无法报销
资金差额显示处理方式
> 0待退实际收到退款后，在“后续补款”中填写对应负数
< 0待补实际追加资金后，在“后续补款”中填写对应正数
= 0已平账不需要额外确认按钮

系统没有“已退”“已补”“退补完成”或“人工结清”按钮。所有资金变化都直接记录到“后续补款”：正数为补款，负数为退回。

六、活动状态与催办

  1. 没有实际支出且没有拨款：未发生支出。
  2. 资金差额 > 0：待退。
  3. 资金差额 < 0：待补。
  4. 资金差额 = 0 但待报销 > 0：待报销。
  5. 资金差额 = 0 且待报销 = 0：已结清。

创建满一个自然月后，对当前仍存在的待退 / 待补 / 待报销事项进行催办。若资金差额和待报销同时存在，待退 / 待补作为主状态，待报销金额作为辅助信息显示，不会被隐藏。

七、客户案例验算

自动无法报销规则关闭

字段金额
实际支出5888
已报销5777
无法报销0
待报销111
首次预支6000
后续补款0
资金差额待退 223

5888 = 5777 + 0 + 111

6000 + 0 − 5777 − 0 = 223，因此此时显示待退 223。

开启“自动将未报销余额计入无法报销”

开关开启的瞬间，“无法报销”必须立即自动改为并锁定：

无法报销 = 5888 − 5777 = 111

于是待报销自动变为 0，其他金额不变，资金差额重新计算：

6000 + 0 − 5777 − 111 = 112

因此此时显示待退 112。

实际收到退款后平账

收到 112 元退款后，把“后续补款”手工改为 -112：

6000 + (-112) − 5777 − 111 = 0

系统自动显示已平账，不需要额外的退补确认按钮。

八、旧数据迁移

  • 旧“预算金额”直接保留为“初步预算”。
  • 旧“预支金额”迁移为“首次预支”；后续补款初始化为 0。新版后续补款允许为负数。
  • 旧活动的实际支出继续由原有支出明细自动汇总。
  • 旧“经费已手动处理 = 是”迁移为“自动将未报销余额计入无法报销 = 是”，以保留“未报销余额不再继续处理”的含义。
  • 旧备份中的“退补已完成”不再映射为任何状态；如存在资金差额，需用“后续补款”的正负金额把账调平。
