让编码智能体同时改进自己的工作台与大脑

原题：Self-Evolving Coding Agents via Harness-Policy Optimization

一个模型明明已经修改好了代码，却因提交格式错误而失败。应该继续训练模型，还是修改它运行时的工具与提交规则？这篇论文的答案是：两个都改，而且轮流改。

01 / 五分钟看懂

为什么“会写代码”不等于“能交付代码”？

想象一个编码智能体：它读取仓库问题、打开文件、运行命令、修改代码，最后提交补丁。即使模型知道正确的修复方式，也可能因工具调用顺序、上下文提示、时间预算或补丁格式出错而没有真正交付。这些不完全是模型参数的问题。

第一步 · 观察失败找到失败模式

检查任务轨迹：是模型不会修，还是已经修好却提交了空补丁？

第二步 · 改工作台优化运行框架

修改提示、执行步骤和提交检查，固定模型参数，筛选更好的框架。

第三步 · 练模型优化模型策略

固定刚选出的框架，通过可执行测试奖励训练模型，再挑出仍然失败的任务。

论文把外部运行框架称为 智能体运行框架（Harness）：它决定模型看到什么、能调用哪些工具、如何接收反馈、何时结束。把模型本身的决策分布称为 策略（Policy）。框架不是模型权重；它是包裹模型的可执行工作流程。

核心创新：训练后的新模型不只是继续解题，还充当下一轮框架修改者；训练中“所有尝试都失败”的任务，自动成为下一轮框架搜索的重点。优化目标随模型能力一起移动，而不是一直盯着同一批老错误。

论文中的一个具体失败

附录 E 展示了同一模型在一个文档项目任务上的两次运行：它已经修改源码并通过现有测试，却把文字总结当作最终提交。原始框架直接接受了这份无补丁的提交；改进框架拦截空补丁，提示模型生成有效补丁，最终通过任务验证。原文附录 E。

这是作者选取的个案，不能据此推断全部失败都能通过拦截提交修复。论文也指出，框架的接口检查提示在该个案中出现过误报。

02 / 前置知识地图

读懂算法前，先补齐四个概念

智能体轨迹是什么？

轨迹（Trajectory）是一次任务中模型输出、工具调用、工具返回和最终提交构成的有序记录。输入是问题及仓库状态，输出是整个执行过程和补丁。本文用失败轨迹指导下一轮框架修改，用成功/失败轨迹训练模型。

为什么可执行验证比“看起来正确”更重要？

可执行验证器（Executable Verifier）在指定仓库环境运行测试或评测，判断提交是否解决问题，给出二元结果 0 或 1。它避免只凭文字描述判断，但仍依赖测试覆盖率、运行环境和评测集质量。

组相对策略优化如何从成功/失败中学习？

组相对策略优化（Group Relative Policy Optimization，GRPO）为同一道题采样多条轨迹，比较同组奖励高低，把相对更好的行为提高概率。若一组全是失败，奖励没有组内差异，学习信号就很弱。本文使用平衡自适应采样（Balanced Adaptive Rollout，BAR）尽量构造有成功也有失败的组。

框架搜索为什么也会过拟合？

如果反复针对固定小题集挑选框架，框架可能记住这批任务的失败特征，却不适合训练后的新模型。本文每轮更新搜索任务集，缓解“框架目标已经过时”的问题；但新的搜索集仍来自同一训练数据，不等于彻底消除过拟合。

04 / 技术拆解与数学

形式化：到底优化什么？

以下先给出论文原式，再给出明确标记的教学改写。每个公式保留对应的 LaTeX 源，且直接使用浏览器原生数学标记语言（MathML）渲染。

公式 1：框架与策略组成的智能体解决率

论文公式（1）｜期望解决率
J(H,P)=𝔼x∼𝒟𝔼τ∼πH,P(·|x)[y(x,τ)]

用途：给一个框架—策略组合打分；越大代表平均解决率越高。

符号：J 是目标函数；H 是运行框架；P 是模型策略；𝔼 表示期望（按分布取平均）；x 是一道软件工程任务；𝒟 是任务训练分布；τ 是一次完整执行轨迹；πH,P(·|x) 是在任务 x 下由框架和策略共同诱导的轨迹概率分布，其中“·”表示待抽样轨迹，“|”表示给定条件；y(x,τ) 是可执行验证器给出的二元奖励（解决为 1，否则为 0）。下标说明期望所依据的采样分布。

直觉：同一模型换框架后，轨迹分布就可能变化；同一框架换模型也一样。二者共同决定通过测试的概率。

查看核对用 LaTeX 源
J(H,P)=\mathbb{E}_{x\sim\mathcal{D}}\,\mathbb{E}_{\tau\sim\pi_{H,P}(\cdot\mid x)}[y(x,\tau)]

公式 2：框架搜索的目标

论文算法 1 逐一评估候选框架并保留得分最高者。为教学方便，写成下式；不是论文单独编号的原式。

教学等价概括｜算法 1 的框架选择
Ht+1=arg maxH∈𝒞tJ^(H,Pt;𝒮t)

用途：描述“固定模型，只选框架”的一步。Ht+1 是第 t+1 轮选中的框架；t 是从 0 开始的轮次索引；arg max 表示取使目标最大的候选；H 是候选框架；∈ 表示属于；𝒞t 是本轮被评估的候选集合（含保留的当前最好框架）；Ĵ 是在有限搜索题集上测得的经验解决率，帽号表示估计；Pt 是此轮固定的模型策略；𝒮t 是本轮搜索题集；分号强调评分依赖搜索集。

例子：同一模型在 300 道搜索题上，框架甲通过 180 道，乙通过 195 道，选乙；这只是说明选择规则的假设数据，不是论文实验记录。

查看教学 LaTeX 源
H_{t+1}=\arg\max_{H\in\mathcal{C}_t}\widehat{J}(H,P_t;\mathcal{S}_t)

公式 3：下一轮为什么换一批难题？

教学形式化｜对应论文 §2.2 与算法 1
𝒮t+1={x∈𝒟:∑j=1mxyx,j=0}

用途：从策略训练轨迹中选出一次也没解出的任务。𝒮t+1 是下一轮框架搜索集；t+1 是下一轮索引；x 是任务；𝒟 是训练任务集合；冒号表示满足右侧条件；Σ 是求和；j 是同一任务的第 j 次采样，起始为 1；mx 是任务 x 的总采样次数；yx,j 是该次采样的二元成功奖励；0 表示全部失败。

例子：某任务的四次奖励是 0、0、0、0，则进入下一轮；若为 0、0、1、0，就不满足条件。样本量和搜索题集可能随训练改变。

查看教学 LaTeX 源
\mathcal{S}_{t+1}=\{x\in\mathcal{D}:\sum_{j=1}^{m_x}y_{x,j}=0\}

公式 4：策略训练的裁剪目标

原文附录 A 的公式（2）采用裁剪概率比率的组相对优化。其核心是：奖励较好的轨迹增加生成概率，但更新幅度受到裁剪阈值约束。

论文公式（2）｜完整策略损失（可局部横向滚动）
ℒP(θ)=−𝔼i[1|𝒜(τi)|∑u∈𝒜(τi)min(ρi,u(θ)A^i,clip(ρi,u(θ),1−εlow,1+εhigh)A^i)]

用途：最小化损失，等价于在裁剪限制内提高具有正优势轨迹的概率。ℒP 是策略训练损失；P 表示策略；θ 是待更新的模型参数；𝔼i 是对采样轨迹编号 i 取平均；τi 是第 i 条轨迹；𝒜(τi) 是该轨迹中由助手生成的词元位置集合；竖线 |·| 表示集合大小；Σ 对词元位置 u 求和，u∈𝒜 表示只遍历助手词元；ρi,u(θ) 是更新策略与采样策略对相同词元的条件概率比值；Âi 是第 i 条轨迹的组相对优势估计；min 取两项较小者；clip 把比率截断到给定区间；εlow=0.2、εhigh=0.28 是论文所用下、上裁剪阈值；最外层负号把最大化目标改写为最小化损失。

注意：这是附录的实际目标，不应把它简化成“成功就奖励 1，失败就惩罚 0”的普通监督学习。BAR 在采样侧尽量构造混合成功/失败组；它与裁剪损失是不同模块。

查看论文 LaTeX 源（按原文抄录）
\mathcal{L}_{P}(\theta)=-\mathbb{E}_{i}\left[\frac{1}{|\mathcal{A}(\tau_{i})|}\sum_{u\in\mathcal{A}(\tau_{i})}\min\left(\rho_{i,u}(\theta)\widehat{A}_{i},\operatorname{clip}(\rho_{i,u}(\theta),1-\varepsilon_{\mathrm{low}},1+\varepsilon_{\mathrm{high}})\widehat{A}_{i}\right)\right]
训练规模（附录 A）：2,484 道训练任务；第一轮框架搜索随机抽 300 道；每次框架搜索评估 6 个候选；每轮策略训练 50 次优化更新。BAR 每题先产生 8 条轨迹，再筛出 4 条组成成功比例在 25%—75% 之间的组；每批保留 32 组共 128 条轨迹。模型训练使用单节点 8 张 B200 图形处理器，学习率为 10−6。这些都是作者报告的配置。

公式 5：多次尝试至少成功一次的概率

论文附录 B｜pass@k 的组合数估计
pass@k=1−(n−ck)(nk),1≤k≤n

用途：给定同一任务的 n 次运行中有 c 次成功，估计抽取 k 次时至少成功一次的比例。pass@k 是该指标；n 是已有总尝试次数（论文取 8）；c 是其中成功次数，满足 0 ≤ c ≤ n；k 是考虑的尝试数，满足 1 ≤ k ≤ n；括号竖排的二项式系数表示组合数，分母是从 n 次尝试中选 k 次的所有组合，分子是全部选到失败尝试的组合；1 减去它就是至少一次成功的概率。

边界：若 c=0，结果为 0；若 k=n 且 c>0，结果为 1。论文对每个任务计算后再平均，不是用所有任务合并的成功次数代入一次。

查看论文 LaTeX 源
\operatorname{pass@}k=1-\frac{\binom{n-c}{k}}{\binom{n}{k}},\qquad k=1,\ldots,8

公式 6：框架与策略有多少互补收益？

教学计算｜论文表 3 的交叉实验
Δ=(69.5−61.0)−[(64.5−61.0)+(64.4−61.0)]=1.6

用途：量化共同优化相对两项单独优化收益之和的额外增益。Δ 是协同剩余量，单位为百分点；69.5 是最终框架与最终策略组合的解决率；61.0 是初始二者组合的解决率；64.5 是最终框架搭配初始策略的解决率；64.4 是初始框架搭配最终策略的解决率。括号用于分组，减号计算相对基线增益。所有数字来自表 3 的均值，最后得到 1.6 个百分点。

06 / 研究判断

论文真正证明了什么，还有什么没证明？

作者证据支持的结论

  • 在指定模型、框架和三套编码评测上，交替优化优于只优化框架或只优化模型的对照（表 1）。
  • 框架与策略的改进部分可拆开迁移，联合组合在人工验证集上有额外 1.6 个百分点的交互收益（表 3）。
  • 更新难题集合、采用强化学习而非监督微调，以及使用更强外部提议者，各自对结果有影响（表 2）。

不能由现有实验直接推出的结论

  • 不能证明该流程在任意基础模型、其他工具环境或完全开放的真实开发任务中稳定有效；主要实验集中在一个模型家族。
  • “难题”定义为本轮采样中从未成功，既可能是真难题，也可能只是采样偶然性；选择偏差需要额外研究。
  • 框架修改本身可能引入错误或干扰。论文图 4 的“原本必定成功”任务组，最终方案的单次成功率反而下降 2.2 个百分点。
  • 交替优化不等于无限递归提升。论文只展示两轮更新，并未证明长期收敛、单调进步或成本可持续。
本站判断（非作者结论）：这项工作的价值不只是“再训练一个更强模型”，而是把失败诊断、执行环境修正与策略学习联成闭环。它提醒研究者：评测智能体时，必须同时报告模型权重、运行框架、提交协议与验证器；否则所谓模型能力的变化可能混入工程流程的变化。
