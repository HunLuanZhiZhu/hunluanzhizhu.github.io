让智能体自己决定怎样使用电脑

OpenGCUA：迈向完全开放的通用电脑操作系统栈
OpenGCUA: Toward a Fully Open Stack for Generalist Computer Use

不只是把“截图—点击”做得更快，而是让模型决定什么时候看屏幕、该用鼠标还是程序、怎样记住任务进度。论文将电脑操作从单一界面技能提升为可编程、可选择观察方式的系统能力。

阅读入口一 · 五分钟看懂

从“会点击”到“会选择工具”

旧问题：每一步都要看图

传统图形界面智能体（GUI Agent）通常截屏、让模型决定点击位置、执行动作、再截屏。遇到上百行表格或可直接处理的文件，频繁往返模型非常昂贵。

核心变化：程序成为动作

模型不再只输出固定动作列表，而是编写一个短程序。程序内部可以循环、判断、读取命令结果，甚至在一次模型调用中完成多项操作。

更进一步：观察也可选择

执行框架（Harness）不再强制每步截图。模型可要求屏幕截图、无障碍元素树，或只接收程序输出，并持续记录任务状态。

先记住这个区分：论文的第一版主要开放的是执行框架、提示词、评测轨迹、真实设备框架及跨设备接口；尚未发布一款新训练的 OpenGCUA 模型。实验是在八款已有模型上更换代理系统配置，不是训练了新权重后进行对比。原文第 1 节、第 3 节。

一个具体例子：更新 29 条客户记录

只会点击的代理，可能要多次截图并逐条点击；批量动作代理能预先列出操作，却无法在执行中根据中间结果改变后续操作。可编程代理则能遍历记录、按条件只修改状态字段、逐项检查其他字段未变，并把检查结果返回模型。论文第 3.2.2 节给出一条包含 64 行程序、更新 29 条线索状态的真实轨迹。程序执行成功不自动等于业务结果正确，仍需检查。

从零补齐背景

读懂论文前，先认识这六个概念

电脑操作智能体（Computer-Use Agent）

以语言模型为决策核心，读取电脑状态、执行动作、观察结果。输入是用户任务与当前电脑反馈；输出是下一次操作或程序。它不是单纯聊天模型。

图形界面与命令行

图形用户界面（Graphical User Interface，GUI）通过像素、鼠标、键盘操作；命令行界面（Command-Line Interface，CLI）通过命令读写文件和调用程序。前者覆盖可视应用，后者适合结构化批量处理。

无障碍元素树（Accessibility Tree）

操作系统提供的结构化界面节点，例如按钮名称、输入框值和父子关系。它可避免猜测屏幕坐标，但并非所有应用都完整暴露这些信息。

执行框架（Harness）

包围模型的软件层：给模型工具、运行程序、返回观察、管理上下文与权限。论文研究的是把原先由框架固定的部分选择交给模型。

部分任务得分与完整成功

部分得分（Partial Score）允许按完成程度计分；完整成功（Full Success）要求几乎达到评测器的满分。二者不能互换。论文第 3.3.1 节与附录 A 使用这两类指标。

提示词缓存（Prompt Caching）

模型服务可能复用不变的输入前缀以减少重复计算。频繁插入大截图会破坏复用；按需截图和分批淘汰旧图片可能提高缓存命中率，但不保证每次都减少总成本。

论文特有机制 · 结构图

三项决策如何形成一个可编程的代理循环

与传统流程的关键差异是模型同时决定观察、行动和任务组织，而不只是点击坐标。原文形式化的动作是“程序”而不是“一个鼠标事件”；执行框架仍负责实际执行、权限边界和反馈。模型的任务状态标记也只是模型自述，不能取代外部验收。

阅读入口二 · 技术拆解

形式化：模型到底输出什么？

原文第 2.1 节的公式（1）将代理策略定义为三个联合决策：选择额外观察、选择程序、更新工作状态。这里的“联合”表示一次策略采样决定三部分，不意味着三者在物理执行上同时发生。

原文公式（1）：联合决策策略
(qt,pt,mt+1)∼πθ(·|mt,ot)
查看核对用的 LaTeX 源(q_t,\ p_t,\ m_{t+1})\sim\pi_\theta(\cdot\mid m_t,\ o_t)

全部符号：t 是当前决策步索引；t+1 是下一步；qₜ 是本步请求的额外观察类型集合（截图、无障碍树或空集合）；pₜ 是本步生成的可执行程序；mₜ 是本步开始时的工作状态，包含任务目标、计划及保留的历史；mₜ₊₁ 是更新后的工作状态；oₜ 是当前可用观察；π 表示随机策略分布；θ 是策略参数；πθ(·|mₜ,oₜ) 表示在给定工作状态与观察后，对三元决策的条件概率分布；· 是待采样结果的占位符；∼ 表示“从分布采样”；竖线表示条件。下标用于区分时刻，括号构成有序三元组。

直觉例子：当前只需要整理一个文件夹时，模型可以让 qₜ 为空、pₜ 是文件操作程序，并把“已生成文件，待确认”写入 mₜ₊₁；如果要确认按钮是否已生效，则可以请求截图。这是教学情景，并非原论文评测记录。

程序运行后，系统会得到命令输出及可选的视觉或结构化观察。原文公式（2）写出了下一轮模型接收到的观察构成。

原文公式（2）：反馈与可选观察的组合
ot+1=(et,{vq(st+1)}q∈qt)
查看核对用的 LaTeX 源o_{t+1}=\bigl(e_t,\ \{v_q(s_{t+1})\}_{q\in q_t}\bigr)

全部符号：oₜ₊₁ 是下一步输入给模型的观察；eₜ 是本步程序执行输出（例如命令标准输出或接口响应）；sₜ₊₁ 是程序执行后的电脑状态；qₜ 是上式中模型选择的额外观察类型集合；q 是遍历该集合时的单个观察类型；v_q 是针对类型 q 的观察函数，例如生成屏幕截图；v_q(sₜ₊₁) 是对更新后电脑状态应用该观察函数的结果；∈ 表示集合成员关系；花括号及其下标表示“收集集合中每个观察类型产生的结果”；最外层括号是“执行输出与额外观察集合”构成的二元组；t 和 t+1 仍是前后相邻步骤。

极端情形：若 qₜ 是空集合，第二项就是空集合，模型只收到 eₜ；若请求截图，第二项多出截图。无论哪种情形，执行输出都保留。这是公式的直接推论。

原文第 2.1 节还给出公式（3），把早期“图形界面＋命令行”的批量操作智能体表示成上述通用策略的受限特例。这个公式解释了为什么仅给智能体增加命令行，还不等于允许它自主选择观察和组织工作。

原文公式（3）：批量图形界面＋命令行代理的三个约束
qt≡{截图}, pt=(a1,…,an),ai∈𝒜GUI∪𝒜CLI, mt+1=h(mt,ot)
查看核对用的 LaTeX 源q_t\equiv\{\text{screenshot}\},\qquad p_t=(a_1,\dots,a_n),\ a_i\in\mathcal{A}_{\mathrm{GUI}}\cup\mathcal{A}_{\mathrm{CLI}},\qquad m_{t+1}=h(m_t,o_t)

完整符号释义：t 为当前步，t+1 为下一步；qₜ 是额外观察集合；≡ 表示此处被固定为恒等选择；花括号中的“截图”（原文 screenshot）表示每一步都要求截图。pₜ 是本步预先排好的动作序列；a₁ 到 aₙ 是序列中第一个到第 n 个动作；n 是序列长度，i 是取值从 1 到 n 的动作位置索引；∈ 表示属于；𝒜_GUI 与 𝒜_CLI 分别是图形界面动作集合与命令行动作集合，∪ 是集合并集。mₜ、mₜ₊₁ 是更新前后的工作状态；oₜ 是本步观察；h 是由执行框架固定的状态更新规则，括号中的两个量是其输入；等号表示确定的约束，而非模型自主选择。

极端例子：假设固定批量有 n=2 个动作，即“打开表格、点击保存”，即使第一个动作失败，第二个动作仍按预排列表执行；通用代理则可以在程序内部先检查打开是否成功，再决定是否保存。这是解释两种动作组织方式的教学例子，并非论文实验轨迹。原文第 2.1 节公式（3）及第 3.1 节。

程序执行和批量动作，不是同一个东西

批量动作（Batched Actions）是模型预先列好若干动作，执行时通常不能依据前一个动作的反馈改变后续列表。代码执行（Code Execution）则允许程序内部依据实时结果进行条件判断、循环和校验。论文第 3.1 节把图形操作与命令行调用放入同一个 Python 程序，框架负责语法检查、执行及错误回传。

可执行程序的教学伪代码（不连接真实设备）：

读取目标表格中的每一行 对每一行： 如果该行的状态不是“已完成”： 修改状态字段 再次读取该字段进行校验 输出已核验的行数与异常记录

程序中“读到结果再判断”是核心。此处是教学伪代码，不是论文附录的原样代码，也不会在本站运行任何设备操作。

从框架转移给模型的选择

原文第 3.2 节讨论按需截图、持久任务清单、动作意图标注，以及由框架管理的滚动截图缓存和微压缩。注意最后两项仍是框架策略，并不是所有上下文管理都已经交给模型。第 3.3.5 节表 4 显示，按需截图使 Qwen3.8-Max 的输入缓存命中率从 75.6% 提高至 86.1%，DeepSeek-V4.1-Flash 从 61.9% 提高至 76.3%；它们的任务得分也有所提高，但步数未必同步减少。

真实设备为什么比基准更难

原文第 4 节指出，真实电脑可能有人同时使用、前台窗口并非目标窗口、任务要求中途变化、登录状态过期。跨设备软件开发工具包（Software Development Kit，SDK）要求每项操作显式绑定设备、应用、窗口或标签页，避免因为焦点变化而误操作；还把“捕获观察”与“把观察交给模型”分开，允许程序先过滤信息。

消融实验：哪些组件贡献了什么？

第 3.3.4 节将单步图形操作、批量图形操作、批量图形加命令行、代码执行进行比较。对于 GLM-5.3-Flash，批量图形加命令行到代码执行，得分从 55.8 升至 63.2；对于 Qwen3.8-Max，步数从 66.1 降至 54.9。第 3.3.5 节再逐项加入按需截图、任务清单、动作意图和上下文管理；并非每一项都提高得分。尤其动作意图是为了可解释性而非单纯刷榜。

真实设备：初步证据不能外推成全面排名

第 4.3.3 节表 5 的四项 macOS 任务包括工作簿处理、表单填写、商品研究、酒店比较。选定运行中，GPT-6 Astra 完成 4/4 项，平均每任务 34.5 次模型调用、12.9 千输出词元；Qwen3.8-Max 完成 3/4 项，平均 50.8 次调用、73.4 千输出词元。论文同时报告后者的推理词元约为前者的 19.4 倍，但费用按当时模型价格计算，两者并非同一比例。样本只有四项任务、选定运行，不足以证明所有真实设备任务上的普遍排名。

如何计算步数相对减少率？

这是本站为了帮助读者核算表 2 而写的教学计算式，并非论文新增的训练目标或原文编号公式。

教学等价计算：相对减少率
R=100×(1−S新S旧)
查看核对用的 LaTeX 源R=100\times\left(1-\frac{S_{\mathrm{new}}}{S_{\mathrm{base}}}\right)

全部符号：R 是步数相对减少率，单位为百分比；S新（LaTeX 中 S_new）是完整通用代理配置的每任务平均模型调用步数；S旧（LaTeX 中 S_base）是批量图形界面基线的每任务平均模型调用步数；100 是把比例转换为百分数的常量；1 是未减少时的整体比例；分数线表示除法；括号表示先求比值再从 1 中扣除。假定 S旧 大于 0，数据均来自相同模型、相同任务集的两种配置。

算例：选择 Qwen3.8-Max，旧步数 127.7，新步数 57.0，得到约 55.4%。这说明平均模型调用次数降低，并不直接说明真实耗时同比例降低。

批判性阅读

哪些结论成立，哪些仍需谨慎？

作者有证据支持的结论

在相同的 OSWorld-v2 离线子集上，更换执行与观察框架后，八款已有模型的部分得分均提高、模型调用步数均下降。代码执行在消融比较中显示了独立于命令行访问的价值；按需截图可提升输入缓存复用。

证据尚不能证明的事情

本报告第一版没有训练新模型；表 2 的系统级对照不能把所有增益都归因于模型本身。82 个离线任务不覆盖互联网任务；真实设备只有少量选定任务与运行。成本依赖供应商当时的定价和缓存机制；步数、词元、美元与真实耗时不是同一指标。真实电脑还存在权限、焦点、隐私与误操作风险，代码执行能力需要独立安全约束。

本站判断

值得研究的不是“所有代理都改用脚本”这样简单的口号，而是将观察策略、动作语言、上下文管理、资源绑定和验证作为可消融的系统设计变量。下一步应在固定模型与任务条件下做更广泛的真实设备对照，并报告失败恢复、权限边界及端到端耗时。
