01 / 直觉入口

五分钟看懂

想象你正在操作一个实时生成的视频游戏：你按下“向左”，画面却继续沿旧方向走了几秒。问题可能不是模型算得慢，而是新内容只能在整段视频交接时插入。

问题：响应被整段边界卡住

模型快，不等于操作响应快

传统方案把多个时间潜变量一起生成、一起提交播放。哪怕推理提前完成，新的操作也可能要等下一个完整片段的播放边界。

变化：预测和确认拆开

一次想远，逐组交付

模型仍在较大的双向窗口里联合预测；播放器每次只确认少量已准备好的输出。其余未来暂存缓存，不必立即兑现。

更新：只改未兑现的未来

新指令来时重算后缀

已经播放或锁定的前缀不可改；控制器从最早可行边界重新采样后续内容，并继续利用旧前缀保证播放不中断。

核心区别：这是推理时的服务调度与缓存策略，作者没有把它描述成新的扩散模型训练目标。它不是“先粗糙生成，再逐帧修补”，也不是在双向窗口内部改成因果注意力。参见原文第 3.2—3.3 节。

输入是什么？

已有视频前缀、当前控制指令，以及模型需要的条件状态（例如历史键值缓存，或边界图像）。

输出是什么？

可按组播放的新视频与可撤销的未来预测；当指令改变时，只让后缀失效并重新生成。

02 / 先修知识地图

理解算法前，先补四个概念

每张卡片都按“是什么 → 输入 → 输出 → 本文用途”组织；熟悉视频生成的读者可直接跳到机制交互。

一、时间潜变量与变分自编码器

是什么：视频通常先由变分自编码器（Variational Autoencoder，VAE）压缩为更短的潜变量序列，模型在压缩表示上生成，再解码回像素帧。输入：像素视频或生成的潜变量。输出：潜变量或解码帧。本文用途：“一组潜变量”可能代表多帧，且必须先经过必要解码才能显示；因此“扩散采样完成”不等于“用户看到了”。

二、双向注意力与自回归续写

是什么：双向注意力（Bidirectional Attention）让同一段内不同时间位置相互感知；自回归（Autoregressive）续写则用已有前缀生成下一段。输入：已生成的历史和当前待采样窗口。输出：联合预测的新片段。本文用途：保留片段内部的双向联合建模，同时让片段之间能够延续。

三、扩散变换器与推理耗时

是什么：扩散变换器（Diffusion Transformer，DiT）反复对噪声潜变量去噪。输入：噪声、条件、历史。输出：新视频潜变量。本文用途：作者分析一次联合采样的耗时和图形处理器并行度，但响应延迟还要计入解码、排队和播放对齐。

四、缓存、提交与可行分支

是什么：缓存存放已预测但尚未全部播放的未来；提交（Commitment）意味着某些像素已交给下游，不能再更改。输入：缓存、已提交前缀、新指令和播放截止时间。输出：一个合法的重算起点。本文用途：只有上下文就绪、截止时间可达、解码器状态有效时，才可以重算可撤销的后缀。

已提交旧指令缓存等待重算新指令缓存

教学规则：更换指令会使未提交部分等待重算；真实系统只在满足公式 10 的截止时间等条件时启动，并且播放在生成状态仍会继续。这里把生成过程折叠为一次“生成完成”操作。

为什么补充噪声潜变量？

假设只想先交付第一组，仍可在后面附上若干噪声组，让双向注意力看见更长的候选未来。与每次都丢掉这些填充组不同，论文把完整预测保存下来，指令不变时继续复用。

如何让双向模型接续？

对于部分模型，可直接保留前缀键值缓存；对于图像条件续写模型，论文第 3.3 节把保留的边界图像解码后重新编码为模型预期的首帧潜变量。两条路径的条件信息与成本不同，不能混为一谈。

05 / 研究级技术拆解

从生成分布到截止时间守卫：十组可核对公式

以下公式依据官方 HTML v1 第 3 节和附录 A—C；原文编号保留，未编号定义明确标注。每式提供原生数学标记语言排版、LaTeX 核对源、符号词典与最小数值例子。

公式 01

潜变量组与播放时长

原文第 3.1 节（无单独编号）

把模型一次联合采样的“潜变量组数”换算成播放秒数；后续所有等待时间的下界都依赖这个周期。

δ=rf,T=Kδ=Krf
核对 LaTeX 数学源
\delta=\frac{r}{f},\qquad T=K\delta=\frac{Kr}{f}

完整符号词典

δ
单个时间潜变量组对应的播放时长，单位秒。
r
每组时间潜变量对应的像素帧数，单位帧／组。
f
目标播放帧率，单位帧／秒；不是显卡实际生成吞吐率。
T
整段联合采样视频覆盖的播放时长，单位秒。
K
一次双向联合采样的时间潜变量组数，正整数。
＝、／
等号与除法；后一种写法由前两式代入得到。

如何理解：例如每组代表 4 帧、每秒播放 16 帧，则一组是 0.25 秒；联合预测 20 组，整段覆盖 5 秒。这是按定义计算的教学示例，不是某个实测部署配置。

公式 02

端到端响应的三个阶段

原文公式（1）

延迟不仅由神经网络推理决定，还包括排队、资源与播放边界等待。

R=tstart−tarrivalC=tready−tstartQ=tplayback−treadyL=R+C+Q
核对 LaTeX 数学源
R=t_{\mathrm{start}}-t_{\mathrm{arrival}},\quad C=t_{\mathrm{ready}}-t_{\mathrm{start}},\quad Q=t_{\mathrm{playback}}-t_{\mathrm{ready}},\quad L=R+C+Q

完整符号词典

R
从新条件到达至生成启动的等待，单位秒。
C
从生成启动至第一组可交付输出就绪的关键路径时长，单位秒；包括必要的扩散变换器采样、解码等，不等于完整视频段耗时。
Q
输出已就绪但尚未显示的等待，单位秒。
L
条件到达至第一组新条件视频显示的响应延迟，单位秒。
t_start
生成任务启动的墙钟时间。
t_arrival
新指令到达服务系统的墙钟时间。
t_ready
第一组可交付视频就绪的墙钟时间。
t_playback
该组视频实际显示的墙钟时间。
下标 start／arrival／ready／playback
分别标记启动、到达、就绪、播放四种事件，不是乘法。

如何理解：假设排队 0.2 秒、生成 1.6 秒、等待播放 0.1 秒，则总响应为 1.9 秒。论文强调：单看生成耗时会漏掉其余两段。

公式 03

一次联合预测如何产生缓存

原文公式（2）

模型一次联合生成一整段，先交付开头，其余预测暂存在缓存中；改变指令时只替换尚可修改的后缀。

核对 LaTeX 数学源
\widetilde{Y}_{j}\sim p_{\theta}(\cdot\mid\mathcal{H}_{j},c),\qquad |\widetilde{Y}_{j}|=K

Ỹⱼ
在第 j 个分支位置生成的候选潜变量序列；波浪号表示“候选预测”，下标 j 是分支位置索引。
∼
表示从右侧条件概率分布采样。
pθ
由模型参数 θ 定义的条件生成分布；θ 是模型权重。
·
概率分布的待采样自变量位置，而不是一个额外观测。
ℋⱼ

∣

公式 04

生产／消费双状态调度器

原文公式（3）；状态名为论文技术标识

每次事件先更新寄存器，再检查是否能启动新生成任务；播放器在两个状态下都可以继续消费已就绪的旧缓存。

核对 LaTeX 数学源
(z^{+},x^{+})=\begin{cases}(\mathsf{Produce},\operatorname{Launch}(\bar{x})),&g(\bar{x},t),\\(\mathsf{Produce},\bar{x}),&\bar{J}\ne\varnothing,\\(\mathsf{Consume},\bar{x}),&\text{otherwise}.\end{cases}

完整符号词典

z⁺
处理事件后的控制状态；上标“＋”表示事件后，不是加一。
x⁺
处理事件后的寄存器集合。
x̄
先由当前事件更新得到的寄存器集合；上横线是中间状态标记。
g(x̄,t)
在时间 t、寄存器 x̄ 下的启动守卫：空闲、确有更新或补充需求、且存在可行分支。
t
当前墙钟时间。
J̄

∅
空集合／无任务。

原文启动操作：锁定前缀、作废可替换后缀并启动完整的联合采样任务。
Produce／Consume
原文状态名称，分别表示“生产中”和“消费缓存”。
z、x

≠、{…

如何理解：“生产中”不代表播放暂停；状态机管理的是生成工作线程。仅当守卫成立才允许发起新任务，不能每显示一帧就重新采样。

公式 05

固定整段提交的等待下界

原文公式（4）；附录 A.1 命题 1

若新内容只能在整段播放边界接入，那么均匀到达的孤立请求，平均还要为“对齐整段”额外等待至少半段时长。

完整符号词典

t_playback^min
理论上最早允许的播放边界时刻；上标 min 表示最小值。
t_arrival
新条件到达时刻。
C
固定的生成关键路径时长，单位秒。
T

⌈·⌉

L

≥
下界，不是所有真实系统都取等号。
1／2

如何理解：若 T 为 5 秒、C 为 1.6 秒，平均延迟下界为 4.1 秒。注意：这里的半段等待已包含生成前后合计的对齐等待，不能再额外重复加一次排队等待。

t_start
对应生成任务开始时间。
C

δ

公式 07

生成任务阻塞带来的残余等待

原文公式（6）；附录 A.3 公式（9）

假设一个工作线程每 T 秒执行一个不可中断、长 C 秒的任务，且 C 不超过 T；新指令随机到达时可能被在途任务阻塞。

𝔼[R]=C22T,𝔼[L]=C+C22T+𝔼[Q]
核对 LaTeX 数学源
\mathbb{E}[R]=\frac{C^{2}}{2T},\qquad \mathbb{E}[L]=C+\frac{C^{2}}{2T}+\mathbb{E}[Q]

完整符号词典

𝔼[R]
生成前残余等待 R 的期望，单位秒。
𝔼[L]
总响应延迟的期望，单位秒。
𝔼[Q]
第一组输出就绪后播放对齐等待 Q 的期望，单位秒；未被本式固定为 δ／2。
C
单次不可中断生成任务及新分支交付的时长，单位秒；本推导将两者设为相同。
T
任务启动的参考周期，单位秒，要求 C≤T。
C²
生成时长的平方；使等待随 C 增长呈二次项。
2
来自均匀残余任务时长的平均值 C／2。

如何理解：取 T＝5 秒、C＝1.6 秒，平均残余等待为 0.256 秒（原文附录 A.3 的算术示例）。若生成占满整个周期，细粒度交付不一定更快。

公式 08

浪费多少预测就多花多少计算

原文公式（10），正文公式（7）为近似成本解释

没有条件更新时，缓存复用不增加完整扩散采样次数；有更新时，作废的预测会拉高每个实际播放组的采样成本。

核对 LaTeX 数学源

被丢弃而未播放的预测组比例，范围 0≤w<1。

06 / 实验与证据

质量、延迟与代价必须分开看

论文报告三类证据：视频质量（不同窗口的模型配置）、单次前向耗时（硬件形状剖析）、真实服务响应（完整推理、解码与播放链路）。它们不是同一个指标，不能混用。

原文表 1 · 视频质量

79.00 → 82.13

Wan1.3B、480p、四步采样，窗口组数从 1 变成 21 时，视频综合评分由 79.00 升至 82.13。不同窗口经过各自训练，不能解释为仅推理时改一个参数。

原文表 2 · 单次前向

77.5 与 78.6 毫秒

Wan1.3B、480p：窗口 1 在单张 H200 的一次前向为 77.5 毫秒，窗口 7 在八卡序列并行下为 78.6 毫秒。GPU 数量不同，不是等硬件成本比较。

原文表 3 · 服务延迟

4.49 → 1.42 秒

Sol-H3、480p、长段、低频更新时，传统整段提交与推测式采样的响应中位数对比。高频更新对应 4.45 → 1.41 秒；两者都未出现播放停顿。

如何判断是否真的改善？

优势有明确边界

原文表 3 的 Sol-H3 长段配置在低频更新下，中位延迟降低 3.07 秒（4.49 减 1.42），但原文第 4.3 节另报告的平均延迟下降为 2.814 秒；中位数差与平均下降不是同一个统计量。

不能忽略负面指标

LTX-2.3 长段低频下，中位延迟从 4.82 降至 2.39 秒，但停顿率从 0.069% 升至 0.204%。短段的急切执行（非图捕获）有约 19.7% 停顿，提示服务优化不能只看延迟。

实验条件与可比性：Wan 的视频质量基于 Toy6K 训练，VBench 在 946 条提示、五种随机种子下评估；LTX 的质量使用内部 8 千视频训练集和 32 个内部评测案例。单次前向的剖析不包括完整解码与采样循环。线上服务采用 B300 图形处理器配置，不应把 H200 前向耗时当成端到端延迟。来源：原文第 4.1—4.3 节，表 1—3。
07 / 研究判断

作者结论、证据限制与本站判断

作者报告的贡献

大窗口双向联合预测可以与小粒度播放确认共存；在指令不变时复用缓存，在指令变化时守卫式重算可撤销未来，避免传统整段播放边界造成的等待下界。作者用三种视频生成模型的服务对照支持这一机制。

尚未解决的问题

频繁变化的指令会浪费更多完整采样调用；双向注意力可能让已保留的键值缓存含有后来废弃的未来信息，简单删除后缀缓存未必能彻底消除污染。不同模型的条件续写接口和解码成本也各不相同。

本站分析（非作者实测结论）：这项工作把实时性问题重新定位为“推理计算、缓存承诺与播放截止时间之间的协同调度”。它的成功取决于实际生成速度是否足够快、指令变化是否足够稀疏、缓存一致性是否可维护；不能推论所有大窗口视频模型都能达到约 1.4 秒响应。
