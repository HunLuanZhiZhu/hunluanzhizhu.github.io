# 论文 → 中文交互式 HTML 技术解读

用于 projects/arxiv-insights/ 的站点适配 Skill。设计参考：https://github.com/sukanthoriginal/interactive-paper-explainers （MIT；双层解释、论文专属交互、静态页面）。

本文件是重新编写的生成规范，不包含上游反馈服务器或运行时代码。**不执行热点检索、不配置定时任务、不自行部署或更新未授权文件。** 以下标记为「必须」的规则，不能因为篇幅、时间或视觉效果而省略。

## 零、草稿模板和元数据发布边界（必须先读）

### 提供实际 HTML 模板

- 本 Skill 自带 `assets/paper-page.template.html`，是可复制改造的**草稿页面骨架**，不是仅有文字中的布局建议。模板包含中文标题及英文原题位置、唯一 `paper-meta`、两个阅读入口、前置知识、技术拆解、机制图、结论与参考来源，采用原生静态 HTML/CSS，不请求第三方字体、图片或脚本。
- **模板不可直接发布**：其中所有标题、论文 ID、日期、示例说明、数学区域和 SVG 区域都标为占位符。必须阅读全文并重写对应内容；数学公式需真实 MathML 或本地已验证 KaTeX 排版、保留原始 LaTeX 源且解释全部符号。SVG 必须针对该论文独有机制绘制，不可把模板占位当成合格图示。
- 模板不强制每篇采用同一视觉或交互设计。鼓励依据论文特点另做页面，但无论是否使用模板，都必须遵守本 Skill 全部证据、中文、数学、交互、性能、无障碍及移动端验收条款。
- **推荐用法**：读取模板 → 生成独立 HTML 草稿 → 核实论文与替换全部占位内容 → 检查 JSON 与浏览器 → 作为未发布附件交付。自动运行不得写 GitHub；仅经用户另行明确授权的人工发布流程才可提交文章。

### 三种日期不能混淆

| 字段 | 准确含义 | 草稿阶段 | 人工发布阶段 |
| --- | --- | --- | --- |
| `published` | arXiv 官方首次发表日 | 核实原文；未核实则保留显式草稿占位并报告 | 必须是已核实、合法的 `YYYY-MM-DD` |
| `date` | 论文在**本站实际归档的日期**，并非原论文首发日 | 尚未归档时可使用模板中的显式无效占位 `YYYY-MM-DD`，**不要猜测日期** | 必须填写真实有效的日期字符串；`null`、空白、占位值一律拒绝 |
| `added_at` | 论文在本站**首次正式收录**的 UTC 时间，决定最新 24 篇排序 | **不得伪造；模板有意不提供此字段** | 首次发布时填写真实、以 `Z` 结尾的 UTC ISO 8601 时间；后续修改不得重置 |

- `draft_generated_at` 可选，仅描述草稿生成时间，**不能代替 `date` 或 `added_at`**。
- 如采用东八区归档日期，应统一依据实际归档时刻换算当地日期，并注明该日历口径；不得直接复制 `published` 当作 `date`。

### 人工正式发布前的阻断式校验

1. 目标路径必须为 `projects/arxiv-insights/papers/<稳定-arxiv-id>/index.html`；目录名与 JSON `arxiv_id` 严格一致（去掉 v1/v2 等版本后缀）；`<head>` 中恰好一个 `type="application/json"` 且 `id="paper-meta"` 的 script，内容必须是可解析的 JSON 对象。
2. **逐字段校验**：`arxiv_id`、`title`、`title_zh`、`published`、`date`、`added_at`、`summary`、`topics`、`heat_note` 必须全部存在；除 `topics` 为非空字符串数组外，均须为非空且真实的字符串。禁止 `null`、空字符串、模板占位或不正确的数据类型。`arxiv_version`、`method_note`、`read_time` 等为可选。
3. `published` 和 `date` 必须是合法真实日历日期 `YYYY-MM-DD`，`added_at` 必须是有效 UTC ISO 8601 时间且以 `Z` 结尾，并保留首次收录时间。绝不自行补造不存在的热度、论文结果或日期。
4. **发布前必须先验证**目标 HTML 的元数据与证据、正文、数学、专属 SVG、响应式及交互；不得把 CI 失败当作正常补齐字段的方法。索引生成脚本 `tools/build_paper_index.py` 是最终兜底校验，不能替代人工发布前的检查。
5. 若已处于**人工授权发布阶段**且持有完整本地检出，可用下面的只读命令调用现有索引构建器的验证函数，检查**所有已在 papers/ 下的论文**，不会写出 `data/papers.json`：

   ~~~bash
   python -c "import runpy; m=runpy.run_path('projects/arxiv-insights/tools/build_paper_index.py'); print('validated:',len(m['load_papers']()['papers']))"
   ~~~

   注意：这个命令会读取已有索引以保留历史元数据，因此**禁止**在只允许只读检索特定文件、不得读取 `data/papers.json` 的自动生产任务中执行；它也**不会检查尚未加入仓库的附件草稿**。这些草稿的元数据必须在发布流程中另行逐项校验。

## 一、研究方向与读者模型（必须）

- **核心领域：机器学习和深度学习**。主要覆盖神经网络、模型架构与训练、优化、强化学习、表征学习、生成模型、多模态、大语言模型、智能体、计算机视觉和机器学习系统。遇到交叉学科论文先说明与机器学习/深度学习的联系。
- **面向 AI 研究生，但不能假设读者理解论文所在的细分领域**。熟悉深度学习不意味着熟悉强化学习、信息论、概率图模型、机器人学或扩散模型。禁止以「显然」「众所周知」掩盖必要的解释。
- 目标是「第一次接触该领域的人能够循序渐进地理解，已经熟悉该领域的人仍可核对完整技术细节」。不能因通俗化删除关键公式、实验条件和限制，也不能因为读者是研究生就略过跨领域概念。
- 在正式讲方法前建立必要的「前置知识地图」。对于每个会妨碍理解的概念，解释：**是什么、为什么需要、输入是什么、输出是什么、在本文的哪一步被使用**；必要时补齐概率、优化、线性代数等基础。与本文无关的基础不必冗长铺陈。
- 全篇默认简体中文；英语术语遵守后面的强制汉化规则。

## 二、输入、原文核查与证据索引（必须）

1. 输入 arXiv ID 或论文 URL、日期以及可选研究关注点。记录原始标题、作者、版本、发布时间、更新日期、原文链接、官方代码链接（仅在真实存在时提供）。
2. 优先阅读全文 HTML/PDF：至少读引言、背景、方法、关键公式、实验设置、主要结果、消融、局限及相关附录。不能靠论文标题、摘要或二手介绍猜测模型细节。
3. 对每个重要公式、实验数字和结论建立可追溯的出处：章节、原论文公式编号、表号、图号或页码。量化指标必须说明数据集、基线、指标定义和增大/减小的意义。
4. **区分**「作者提出/报告」「外部独立验证」「本站分析推断」。不能把作者主张写成经过独立证明的事实；疑问与尚未核实部分明确说明。
5. 如果只拿到摘要或部分正文，必须在页面顶部标「基于摘要/部分正文的初步介绍」，不得编写貌似完整精读的公式推导、实验分析或消融结论。
6. 不大段复制受版权保护的论文文字或直接搬运未经许可的原图。自行根据核实的模型结构重绘机制示意图并引用原文。

## 三、两个阅读入口、四层认知台阶（必须）

页面采用双入口：「五分钟看懂」与「技术拆解」，但不能把技术内容从正式页面中删掉。讲解逻辑应从最容易理解的直觉一路推进到可复核的研究技术细节。

### 第 1 层：问题直觉

第一屏回答三个问题：**作者要解决什么？传统方案为什么困难？论文提出了什么关键变化？** 从真实场景、微型案例、逐步图解切入，不要第一段就堆叠陌生缩写。类比只能辅助理解，必须说明类比的适用边界。

### 第 2 层：补齐跨领域先修知识

为必要知识安排可展开的「预备知识卡片」。按前后依赖解释术语，而不是让读者自行搜索。例如讲解近端策略优化之前，要先说明策略、奖励、策略更新、概率比率和裁剪目标分别在做什么；不能默认读者已经学过强化学习。高级读者可跳过卡片，新读者应能凭页面理解后文。

### 第 3 层：可以操作的机制直觉

以**输入 → 中间表示或步骤 → 输出**梳理算法。针对论文独有的关键机制，制作能切换步骤、改变变量或比较条件的交互图。每次交互说明：改变了什么量、对应哪个公式或模块、结果为何改变。简化的教学模拟必须标清不等同于原模型复现。

### 第 4 层：研究级技术拆解

完整呈现问题形式化、符号和公式、结构、训练/推理算法、实验设置、基线、指标、消融、成本与局限（具体依据论文内容）。对每项效果改进说明「和谁比较、在什么条件、改善多少、代价多大、能否推广」。结尾分开写作者结论、证据局限和本站判断。

「五分钟看懂」覆盖前三层的直觉内容；「技术拆解」应包含第二至第四层的完整专业内容，并链接回必要的预备知识。**不假设读者已经了解论文所属的研究分支。**

## 四、全中文与术语翻译（必须）

**所有面向读者的自然语言应使用简体中文；禁止让英文单词孤立出现在页面正文或界面中。** 英文只有在学术追溯、技术标识等必要场合才保留。

- 专业术语**首次出现统一采用「中文（英文）」**，常见缩写可接在括号中。例如：注意力机制（Attention）、词元（Token）、奖励模型（Reward Model）、近端策略优化（Proximal Policy Optimization，PPO）、消融实验（Ablation Study）。暂无固定译名时先给准确的中文试译，再在括号补原文，不直接抛出英文。
- 后续叙述优先只使用中文；需要与原文的缩写、公式、源代码对应时，可适量沿用已配对介绍过的缩写，但不能用整段英文标签替代解释。
- **论文标题一律提供中文译名，并配对保留原始英文标题**。作者专有姓名、原始文献条目、算法/模型的专名、代码片段、接口、DOI、arXiv ID、公式符号和标准单位可以保留原样；其周围必须有清楚的中文说明，不要篡改原始标识。
- 中文要求覆盖**页面标题、导航、正文、图注、SVG 节点、坐标轴、刻度说明、图例、公式变量释义、按钮、滑杆、动态提示、测验反馈、错误提示和无障碍替代文本**。例如按钮写「下一步」，不要只写“Next”；坐标轴写「训练步数」，不要只写“Steps”。
- 输出前逐项核查所有 HTML 可见内容、SVG 的文字元素及 JavaScript 动态生成的字符串。保留必要英文时，要能说明为何必须保留，且有对应中文解释。

## 五、数学公式必须是真正渲染的数学公式（最高优先级，必须）

### 5.1 源表达式的正确性

- 从原论文逐一核实关键公式，保留准确 **LaTeX 数学源**及来源（公式编号/章节/页码）。区分「论文原式」「为方便教学的等价改写」「带额外假设的教学例子」，不能混为一谈。
- 严格检查上下标、求和/积分边界、变量含义、概率条件、张量形状、梯度、约束和优化方向。改写记号时给出与论文原符号的映射。
- **不能因为数学式太复杂就删除必要的关键公式，也不能用 SVG 流程图取代完整数学定义。** 可以在关键公式旁提供分阶段拆解、直觉解释和图示。

### 5.2 网页必须完成数学排版

- 公式在 HTML 中必须显示为结构正确、可访问的数学排版。优先使用**原生 MathML（数学标记语言）**，保留对应的 LaTeX 源供核对；也可使用**本地托管的 KaTeX 数学排版引擎**及完整配套样式、字体，在生成时或浏览器端完成真正渲染。
- 必须兼容本项目**纯静态、GitHub Pages 子目录部署、无外部 CDN 和无服务端依赖**的架构。本地 KaTeX 资源的路径、样式和字体要真实存在，不可以只在页面引用不存在的文件。
- LaTeX 源码或定界符 **不等于已渲染公式**。如果没有排版引擎，普通 HTML 中的 $...$、\(...\)、\[...\] 只是文本，**不得作为最终成品**。禁止用类似 "L = -1/N * sum(log(p(y|x)))" 的普通字符冒充数学公式，或把完整核心公式替换成无法复制的图片。
- 区分行内公式与独立公式，规范呈现分数、上下标、矩阵、范数、期望、梯度、积分、分段函数、括号层次等；必要时提供公式编号与可访问的文字说明。
- 公式源示例（**这只是核对用的源代码，不是已经渲染的网页公式**）：

~~~tex
\mathcal{L}=-\frac{1}{N}\sum_{i=1}^{N}\log p_\theta(y_i\mid x_i)
~~~

  最终 HTML 应把该源渲染成真正的数学式，而非把上面这行字符串直接塞进正文。

### 5.3 每个出现的公式都必须解释全部变量（最高优先级）

**不论是行内公式、独立公式、补充推导还是交互演示所用公式，只要出现在页面上，就必须解释式中出现的所有变量，不得只解释“重要变量”或假设读者认识常见数学记号。** 每个公式附近须明确说明：

1. **为什么写这个式子**：它计算什么、约束什么、优化什么，和研究目标的关系是什么。
2. **完整符号词典，零遗漏**：逐项解释该公式出现的全部变量与数学符号，包括左侧结果量、右侧输入量、自变量、因变量、模型参数、超参数、常量、索引字母、求和/积分上下界、上下标、希腊字母、随机变量、期望所基于的分布、条件概率、算子和自定义函数。需要时给出各量的单位、维度/张量形状、定义域和取值范围；特殊记号（例如范数、梯度、转置、点积、指示函数）说明运算含义。常见运算符无需反复解释基础算术，但不能遗漏会影响公式理解的专用记号。
3. **直觉与数字例子**：解释每一项如何影响结果；复杂时提供最小可计算实例或极端情形，并说明属于教学演示还是原论文数据。
4. **推导依据**：必要推导的步骤、附加假设与原文定位；不得把解读者的推测写成作者证明。
5. **与交互联动**：若有滑块或变化曲线，说明用户操作的是哪个数学符号，以及变化规律对应的真实数学关系。禁止用随意数值或随机动画冒充论文实验数据。

**逐式检查规则**：每出现一个公式，逐一提取其中的变量与非显然符号，与紧邻的中文符号解释核对；没有解释的立即补充。前文已经定义过的符号允许使用就近的清晰回链指向同页术语解释，但不能要求读者自行推断，也不能只提供远程外链。同一字母在不同公式中含义变化时必须重新定义。**任何公式只要存在未解释变量，即视为未通过验收。**

### 5.4 公式验收不可只读 HTML 源码

- **必须在真实浏览器中检查桌面和移动端渲染**：不能出现原始 LaTeX 控制符、乱码、缺字、错位上下标、被裁切的公式、溢出或模糊不可读的字号。长公式应换行或可横向滚动。
- 检查 MathML 或本地 KaTeX 的实际效果、可访问性、深色模式、相对路径、字体依赖与键盘操作。只检查 HTML 语法、文本或源代码**不算公式渲染验收**。
- 如果无法运行浏览器验证，必须报告「公式渲染未实际验证」，不可声称页面完全合格。

## 六、SVG 与互动图必须教会读者（必须）

- 每篇至少一张与**论文具体机制**有关的内联 SVG（例如模型结构、数据流、优化回路、注意力变化或实验对照），不能用通用装饰图充数。
- 优先有至少一个有意义的可操作交互（控制参数、单步播放、切换模块或消融条件等）。若不适合交互，说明原因，改为可逐步解释的 SVG，而不是硬造可点按钮。
- 交互必须有清楚的操作提示、初始状态、状态反馈、复位方法，以及“操作 → 数学量/步骤 → 含义”的解释。演示中的数值应来自明确的数学关系或论文数据。示意图醒目标明「概念示意，非论文测量数据」，不捏造实验曲线、数值或基准成绩。
- 图示的所有标签、坐标轴、箭头说明及动态文字按全中文规则处理；提供文本替代说明，保证移动端字号、响应式、对比度和键盘可操作。尊重减少动效偏好（prefers-reduced-motion）。
- 保持严肃、清晰的学术视觉效果。原生 HTML、CSS、JavaScript、内联 SVG 优先；数学引擎如有需要仅用本地依赖，不额外引入统一构建链或外部反馈服务器。

## 七、移动端优先的阅读与交互体验（必须）

- **从窄屏开始设计**：默认以手机阅读为主要场景，同时保持桌面端完整体验。使用响应式布局、合理的文字层级与留白；正文在手机上推荐不少于 16 像素的基础字号，不依赖双指放大阅读正文。
- **禁止整页横向溢出**：在 320、375、430、768 CSS 像素宽度等典型视口，以及手机横屏下，导航、长标题、表格、代码、SVG 和图注不得撑破页面。长公式或宽表格可在自身容器内横向滚动，必须有明显提示，不能造成整个页面横向滚动，也不能把公式缩小到无法识别。
- **公式移动端专门适配**：复杂公式保留结构与完整符号解释；优先合理分行，必要时允许公式容器局部滚动。公式编号、变量解释卡片与相关图解不得遮挡或错位；不得为了适配手机删除公式或省略变量说明。
- **适合触控而不依赖悬停**：按钮、滑块、步骤切换、知识卡片和图表交互应具有清楚的点击状态、触控反馈和明确的文字标签；重要功能不得只靠鼠标悬停触发。交互目标建议至少达到 44×44 CSS 像素，控件间留出足够间距，同时保障键盘与屏幕阅读器的使用。
- **SVG 与图表在小屏上仍可读**：使用 viewBox 和自适应布局，必要时重排节点、分步展示或提供局部缩放/滚动及同步文字解释。不得简单把桌面图整体缩成看不清文字的缩略图；图例、轴名、标注仍须按全中文原则处理。
- **性能与无障碍**：移动端不应依赖高性能图形设备或长时间动画才能读懂论文；采用轻量脚本，提供加载与错误提示、减少动效支持、可见的键盘焦点；不得禁用用户页面缩放。
- **必须实机或浏览器移动设备模拟验证**：实际检查窄屏排版、触摸操作、中文文字、数学渲染、局部滚动、横屏、页面缩放和主要交互。只在桌面浏览器缩小窗口或静态检查 CSS，不能代替完整的移动端验收。无法验证的项目必须如实列出，不能宣称已适配。

## 八、文件产出与登记（必须）

自动生产只生成经验证的完整 HTML 附件，不写入仓库。经用户在普通对话明确批准后，独立发布阶段才可通过 GitHub 插件提交至 projects/arxiv-insights/papers/%ARXIV_ID%/index.html。禁止自动生产读取或修改 data/papers.json。HTML 的 `<head>` 必须有唯一 `<script type="application/json" id="paper-meta">`，内容为合法 JSON 对象。**正式发布之前**必填 `arxiv_id`、`title`、`title_zh`、`published`、`date`、`added_at`、`summary`、`topics`、`heat_note` 并通过本文件「零、草稿模板和元数据发布边界」的阻断校验。`date` 必须是本站真实归档日的合法 `YYYY-MM-DD` 字符串，**不得为 null、空字符串或模板占位**；`published` 是核实的论文首发日，不可混用；`added_at` 表示本站首次收录 UTC ISO 8601 时间，未发布草稿不得伪造，首次发布时补齐，日后不可覆写。稳定 ID 必须与目录一致，热度不得虚构。页面链接须适用于 GitHub Pages 子路径，包含返回该子项目索引、原文及可核验代码链接。

推荐页面布局：**中文论文标题+英文原题配对 → 问题导览 → 五分钟看懂 → 前置知识 → 技术拆解（公式/方法/实验）→ 交互式机制 → 结论与局限 → 原文与参考来源**。双入口可以用标签页、锚点或可展开章节组织，不能为了省空间隐去深度内容。

完成全文核对与真实页面检查后，校验 HTML 草稿内 `paper-meta` 元数据；独立人工发布后，索引才由 GitHub Actions 执行 `tools/build_paper_index.py` 自动生成，**AI 不直接写 data/papers.json**。遵守项目 README 的字段约定，使用剥离版本号的 arXiv ID 去重。自动生产只交付 ChatGPT 附件，不写入仓库、不启动定时任务、不自行发布。

## 九、草稿交付前强制验收清单

- [ ] 研究定位面向机器学习和深度学习；前置知识足以让不熟悉细分领域的读者读懂。
- [ ] 具有「五分钟看懂」和「技术拆解」双层内容；先有问题直觉，最终保留研究级数学和实验细节。
- [ ] 中文译名覆盖所有读者可见自然语言及交互图示；专业英文首次为「中文（英文）」；原论文标题同时保留准确的中英文对照。
- [ ] **每一个出现的公式**都对照原文或标明教学改写，保留 LaTeX 源并真正渲染；其**全部变量、索引、上下标、参数、常量与非显然运算符均有中文解释**（可就近链接回同页已定义条目），不存在未释符号。
- [ ] 公式已在真实桌面与手机浏览器验证：可读、无乱码、无缺字、无错误定界符和布局溢出；没有验证不能宣称合格。
- [ ] 至少有一张论文特有的 SVG 机制图；互动有明确教学目的，区分概念演示与论文实测。
- [ ] 重要结论和量化数字可定位到原文；论文版本、实验设置、基线、局限和作者/解读者立场清楚。
- [ ] **移动端专门验收**：检查 320、375、430、768 CSS 像素宽度及横屏，正文无需缩放可读，整页无横向溢出，长公式/宽表格仅容器内滚动，SVG 标签可读，触控目标足够大，重要操作不依赖悬停；验证手机触摸与键盘、深色模式、页面缩放、链接及浏览器错误。未验证项逐项声明。
- [ ] 模板所有占位内容均已替换（若使用模板）；正式发布前检查唯一有效 paper-meta、目录 ID、真实 published、非 null 的有效 date、首次收录 added_at、真实来源及非空 topics；**不合格即停止发布**。
- [ ] 只修改已授权路径，不引入不可信远程脚本，不启动调度或擅自覆盖/发布现有文章。

## 禁止事项

不得以普通字符代替数学公式，不得留下任何一个未解释的公式变量；不得将桌面页面直接缩小冒充移动端适配；不得以纯英文标签代替中文讲解；不得假定读者了解论文所在细分领域；不得为了制造互动虚构数据、公式或作者结论；不得把「HTML 能打开」当成「学术和渲染都已验证」。
