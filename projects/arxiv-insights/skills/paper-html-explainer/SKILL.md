# 论文 → 双层中文 HTML 解读

用于 `projects/arxiv-insights/` 的原创站点适配 Skill。设计参考：
https://github.com/sukanthoriginal/interactive-paper-explainers （MIT，双层阅读与交互式论文解释、静态发布）。

不复制上游的评论服务器、运行时库或必须逐阶段询问人工批准的流程。此文件只规定未来生成文章的质量与输出格式，**不会自动执行或发布**。

## 输入与核验

输入 arXiv ID 或论文原文 URL、归档日期、必要的读者兴趣。优先读取完整 HTML/PDF 原文，不以模型记忆或社区概览代替。记录论文版本、作者、发布日期、原文链接、代码链接（若真实存在）。没有获得完整论文则标注“基于摘要的初步介绍”，禁止伪装为技术精读。

制作一份可追溯的证据备忘：关键方法与公式对应章节/页码；每一项实验数字对应论文中的表、图或文本；尤其区分实验设置、消融、跨数据集结果、作者宣称与评论者评价。争议或未验证内容应注明不确定性。

## 解读结构：两种阅读深度

1. **五分钟看懂**：从真实问题出发，以具体场景、直觉类比和逐步示意图介绍研究动机、核心想法、与旧方案的差异；第一次出现术语时给出准确的中文释义。类比后写清适用边界，不能以类比替代技术定义。
2. **技术拆解**：问题形式化、整体架构、关键算法/推理流程、主要公式与变量、实验设置与结果、对照及消融、局限性和适用条件。重要结论附原文定位依据。
3. **读后判断**：该工作解决了什么、没有解决什么、结果是否依赖基准或数据条件、可能的复现阻碍；标注这是原文结果、外部验证还是解读者推论。

## 图示与交互标准

- 每篇至少有一张**内容相关的内联 SVG**：例如架构数据流、训练反馈回路、注意力流向或实验对照。不得把通用装饰当成解释。
- 有真实机制可演示时，提供可操作的小组件（滑杆、逐步播放、切换消融、展开子模块）；交互后的数值应来自明确公式、模型或论文数据。只作示意时必须标明“概念示意，非论文测量数据”。
- 键盘可操作，控件有标签，移动端不溢出；支持 `prefers-reduced-motion`，并为 SVG 给出文本替代说明。
- 优先原生 HTML/CSS/JS 与 inline SVG，不依赖外部 CDN、在线字体或需服务器处理的反馈功能。保持轻量、单页可用。
- 不直接复制论文的长段文字或整张受版权保护的插图；可自行重绘准确标注的机制示意图并附原始来源。

## 输出与登记

单篇文章输出到 `../../papers/<arxiv-id>/index.html`，使用适合 GitHub Pages 子路径的相对链接。页面必须能从 `../../index.html` 返回索引、链接到 arXiv 原文；链接有效、没有假按钮、没有伪造数据。禁止未经验证的公式动画；如果公式过复杂，可用准确的静态 SVG 流程图取代。

完成一篇论文且核查过页面后，再将元数据添加至 `../../data/papers.json` 的 `papers` 列表，字段规范参见项目 README。以去除版本号的 arXiv ID 为稳定键；不要覆盖已有文章。任何输出写入前应先读取目标文件，尊重已有修改。

## 最低审校

- 读者可在第一屏明确知道“这篇研究解决什么问题”；
- 对专业人士，公式、符号、实验结论及适用边界没有实质性歪曲；
- 至少一张具体的机制 SVG 与至少一个有意义的可交互点（如确实不适用，则在报告里说明例外）；
- 每个有量化主张的数字均可定位到原文；
- 在桌面和手机视口检查排版、点击、键盘导航和浏览器报错；做不到时如实说明未验证项。

## 禁止事项

不准为了视觉效果虚构模型性能、指标曲线、作者结论；不以网页生成成功冒充论文已复核。默认仅生成页面，不启动定时任务，不自行发布未经授权的更新。
